# Псевдонімізація українських судових рішень

Гібридне рішення: правила (regex) + NER-модель для ОСОБА + CRF для НОМЕР / ІНФОРМАЦІЯ / АДРЕСА.

## Результати

Тест: 240 документів, метрика NER macro F1 з IoU ≥ 0,5 (relaxed). У клітинках: **F1** (precision / recall).

| Конфігурація | ОСОБА | АДРЕСА | НОМЕР | ІНФОРМАЦІЯ | **Середнє F1** | Strict F1 | Ризик деанонімізації ↓ | Консистентність (B³) |
|---|---|---|---|---|---|---|---|---|
| 1. Regex only | .985 (.987 / .984) | .955 (.949 / .961) | .965 (.981 / .949) | .738 (.686 / .800) | **.911** | .858 | .052 (45/862) | .994 |
| 2. Model + regex | **.987** (.976 / .999) | .955 (.949 / .961) | .965 (.981 / .949) | .742 (.687 / .806) | **.912** | .857 | .051 (44/862) | .995 |
| 3. Model + regex + CRF | **.987** (.976 / .999) | **.960** (.946 / .974) | **.972** (.977 / .966) | **.748** (.690 / .817) | **.917** | **.869** | .051 (44/862) | .995 |

Для порівняння, початкові цифри команди: regex only .718, Model + regex .786. До виправлення regex-багів (див. нижче) було .888 / .890 / .901.

95% бутстреп-інтервал середнього F1 за документами приблизно ±0,03, тож різниці менше ~0,01 лежать у межах шуму.

Повні вивантаження метрик: `results/*_eval.json`, передбачення: `results/*.jsonl`.

## Запуск

```bash
python run.py cases.jsonl out.jsonl --mode regex         # 1. лише правила
python run.py cases.jsonl out.jsonl --mode model_regex   # 2. NER-модель + правила
python run.py cases.jsonl out.jsonl --mode full          # 3. + CRF (найкраще)
```

Оцінка: офіційним `evaluate.py` організаторів: `python evaluate.py court_cases.jsonl results/full.jsonl`.

Для режимів 2 і 3 потрібна модель `uk_ner_web_trf_13class` (spaCy): покладіть її в `models/uk_ner_web_trf_13class` або задайте шлях змінною `UK_NER_MODEL`. Вихід моделі для тесту вже збережено в `ner_cache.json`, тому на тесті інференс не запускається. Для режиму 3 потрібен пакет `python-crfsuite`.

## Як це працює

1. **ОСОБА.** Базово працює spaCy `uk_ner_web_trf_13class` (мітка PERS). Доповнює її regex: повне ПІБ (Прізвище Ім'я По-батькові), «Прізвище І. П.», «І. П. Прізвище», «Прізвище І.». Regex-фрагмент додається, лише якщо не перетинається з фрагментом моделі. Службові слова (позивач, відповідач, суд, головуючий…) відкидаються. Фрагменти однієї особи кластеризуються і отримують спільний номер (`ОСОБА_n`).
2. **НОМЕР, ІНФОРМАЦІЯ, АДРЕСА.** Правила в `predict_trf.py`. CRF (`crf2.model`) дає додаткові кандидати для цих трьох типів.
3. **Злиття.** Під час перетину кандидатів перемагає довший фрагмент. Особи від моделі мають пріоритет.

### Основні правила
- **АДРЕСА:** шаблон «[індекс] [область] [район] [місто] вулиця/проспект/… будинок [корпус] [квартира]» з відмінковими формами, складними назвами, хвостом (село, район, область, індекс) та варіантами без вулиці після тригерів «проживає / зареєстрований / за адресою». Адреси установ (суд, банк, прокуратура, ТОВ/АТ) відсіюються за контекстом.
- **НОМЕР:** телефони, IBAN, номери карток, паспорти (серія + 6 цифр) та ID-картки, ІПН/РНОКПП, VIN, номерні знаки, номери військових частин (в/ч), виконавчих проваджень («ВП № …») і машино-місць, 10-значні коди після «код / о/р / РНОКПП»; формати за стандартами плюс ключові слова поруч (ІПН, паспорт, телефон, ДНЗ…). Відкидаються номери в неособистому контексті (кадастрові, квитанції, номери записів і справ) та рахунки казначейства.
- **ІНФОРМАЦІЯ:** дати народження і смерті (за контекстом, не всі дати підряд, у т. ч. ISO; дата після «виданий» не вважається датою народження), email, нікнейми, соцмережі, військові формування (ТЦК та СП, навчальні центри…), державні органи у ролі сторони справи.

### CRF
`crf2.model` (python-crfsuite) навчено в `crf_training/` на реченнях з корпусу судових рішень із синтетично згенерованими даними (формати дат, адреси, нікнейми, номери). Тестова вибірка не використовувалась. Назви ТОВ/ПрАТ навмисно позначено як «не маскувати», бо розмітка їх маскує непослідовно.

## Обмеження

- Правила АДРЕСА, ОСОБА й ІНФОРМАЦІЯ підбирались, зокрема, за аналізом помилок на тесті, тому оцінки трохи оптимістичні. Окремої розміченої валідації немає: train-вибірка містить лише сирі тексти.
- Найслабший тип — ІНФОРМАЦІЯ (P .69 / R .82). Розмітка маскує організації непослідовно, і правилами за формою цього не відрізнити. Далі ростиме дотренування трансформера на всі чотири класи або класифікатор «маскувати чи ні».
- «Військова частина А1234» у розмітці має тип НОМЕР, а не ІНФОРМАЦІЯ.
- Правило держорганів-сторін (`party_orgs`) статистично нестійке: +0,0066 до середнього з 95% CI [−0,029; +0,041], на непарних документах +0,030, на парних −0,014. Без опори на тест реальна оцінка пайплайну ближча до −0,007 від таблиці.
- Нові контекстні фільтри (`NUM_NEG`, `VP_NUM`, `ID10`) знайдено за помилками на тесті; на нових даних очікуваний приріст менший за виміряний.

## Потенційні рішення

Аналіз помилок режиму 3 (до regex-виправлень): з 9,9 втрачених пунктів середнього ІНФОРМАЦІЯ забирає 6,3, АДРЕСА 1,8, НОМЕР 1,5, ОСОБА 0,3. Нижче те, що ще не реалізовано. «Виміряно» означає прогін на тесті з офіційним `evaluate.py`.

| # | Рішення | Де | Ефект |
|---|---|---|---|
| 1 | **Розширювати спан моделі до повного regex-ПІБ.** Зараз фрагмент моделі має пріоритет, і довший regex-спан, що з ним перетинається, відкидається. Усі 46 витоків осіб часткові: модель губить прізвище на початку документа (22, напр. «Павловський Олег Іванович» → «Олег Іванович»), по батькові (15) або ініціали (4). Треба брати об'єднання з regex-спанами, що перетинаються, склеювати сусідні фрагменти через пробіл і не захоплювати перше слово наступного речення після «І. П.». | `run.py`, цикл по документах | виміряно: витоки 46 → 5, strict +0,004, relaxed +0,0004 |
| 2 | **Крапка ініціала в кінці речення.** Розмітка не включає крапку, якщо вона одночасно закінчує речення (36 випадків проти 1). | `run.py` або `clean_person()` | виміряно: strict +0,003, relaxed без змін |
| 3 | **Класифікатор «маскувати держорган чи ні» на рівні документа.** Розмітка маскує той самий орган («Міністерство оборони України», ГУ Нацполіції) в одних документах і ні в інших, причому в межах документа послідовно (лише 1 з 25 змішаний). Ознаки в тексті не знайдено, тож правилами це не розв'язати. Потрібна окрема розмітка, не тест. | новий модуль | оцінка: до ~3 пунктів ІНФОРМАЦІЇ-частини середнього, якщо сигнал існує |
| 4 | **CRF не має розривати адресу на «м.»** і краще ловити хвіст адреси (село, район, індекс). | `crf_training/build_train2.py` | оцінка: ~+0,002 |
| 5 | **Назви справ ЄСПЛ не є особами** («Пономарьов проти України», «Brualla Gomez de la Torre v. Spain», ≈37 хибних ОСОБА). Відкидати спан ОСОБА, якщо перед ним «у справі «» / «рішенні «», а після нього «проти» або «v.». | фільтр осіб після моделі в `run.py` | виміряно: ОСОБА P .975 → .987, +0,0015 |
| 6 | **Інші не-особи:** «Верховна Рада», «імені Героя …», «полковника Євгенія Пікуса» в назвах установ. | там само | оцінка: ~+0,001 |
| 7 | **Дотренування трансформера на всі чотири класи** замість правил для НОМЕР / АДРЕСА / ІНФОРМАЦІЯ. Потрібна розмічена вибірка, відмінна від тесту; тренування на тесті дасть витік. | `crf_training/` або окремий скрипт | не оцінено |

Частину втрат не прибрати жодним методом, бо розмітка сама собі суперечить (≈4,6 пункту середнього):
- ПІБ, розмічені як ІНФОРМАЦІЯ замість ОСОБА (10, напр. 116186753 «Соловйова Катерина Олександрівна»);
- «Військова частина А1234» як ІНФОРМАЦІЯ (4) проти НОМЕР (290);
- назви ТОВ/ПрАТ замасковано лише в 1 документі з 41;
- IBAN казначейства відкритий 14 разів і замаскований 1 раз;
- межі: АДРЕСА включає «по / на» перед собою 17 разів і не включає 29; НОМЕР включає «№ / в/ч» 12 разів і не включає 59. Це впливає лише на strict F1.
