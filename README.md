# Псевдонімізація українських судових рішень

Гібридне рішення: правила (regex) + NER-модель для ОСОБА + CRF для НОМЕР / ІНФОРМАЦІЯ / АДРЕСА.

## Результати

Тест: 240 документів, метрика NER macro F1 з IoU ≥ 0,5 (relaxed). У клітинках: **F1** (precision / recall).

| Конфігурація | ОСОБА | АДРЕСА | НОМЕР | ІНФОРМАЦІЯ | **Середнє F1** | Strict F1 | Ризик деанонімізації ↓ | Консистентність (B³) |
|---|---|---|---|---|---|---|---|---|
| 1. Regex only | **.983** (.985 / .982) | .918 (.950 / .888) | .911 (.958 / .868) | .740 (.689 / .800) | **.888** | .834 | .058 (50/862) | .994 |
| 2. Model + regex | **.986** (.975 / .998) | .918 (.950 / .888) | .911 (.958 / .868) | .744 (.690 / .806) | **.890** | .833 | .053 (46/862) | .995 |
| 3. Model + regex + CRF | **.986** (.975 / .998) | **.929** (.931 / .927) | **.939** (.938 / .940) | **.750** (.693 / .817) | **.901** | **.852** | .053 (46/862) | .995 |

Для порівняння, початкові цифри команди: regex only .718, Model + regex .786.

Повні вивантаження метрик: `results/*_eval.json`, передбачення: `results/*.jsonl`.

## Запуск

```bash
python run.py cases.jsonl out.jsonl --mode regex         # 1. лише правила
python run.py cases.jsonl out.jsonl --mode model_regex   # 2. NER-модель + правила
python run.py cases.jsonl out.jsonl --mode full          # 3. + CRF (найкраще)
```

Оцінка: офіційним `evaluate.py` організаторів: `python evaluate.py court_cases.jsonl results/full.jsonl`.

Для режимів 2 і 3 потрібна модель `uk_ner_web_trf_13class` (spaCy): покладіть її в `models/uk_ner_web_trf_13class` або задайте шлях змінною `UK_NER_MODEL`. Вихід моделі для тесту вже збережено в `ner_cache.json`, тому на тесті інференс не запускається. Для режиму 3 потрібен пакет `python-crfsuite`.

## Як це працює

1. **ОСОБА.** Базово працює spaCy `uk_ner_web_trf_13class` (мітка PERS). Доповнює її regex: повне ПІБ (Прізвище Ім'я По-батькові), «Прізвище І. П.», «І. П. Прізвище», «Прізвище І.». Regex-фрагмент додається, лише якщо не перетинається з фрагментом моделі. Службові слова (позивач, відповідач, суд…) відкидаються. Фрагменти однієї особи кластеризуються і отримують спільний номер (`ОСОБА_n`).
2. **НОМЕР, ІНФОРМАЦІЯ, АДРЕСА.** Правила в `predict_trf.py`. CRF (`crf2.model`) дає додаткові кандидати для цих трьох типів.
3. **Злиття.** Під час перетину кандидатів перемагає довший фрагмент. Особи від моделі мають пріоритет.

### Основні правила
- **АДРЕСА:** шаблон «[індекс] [область] [район] [місто] вулиця/проспект/… будинок [корпус] [квартира]» з відмінковими формами, складними назвами, хвостом (село, район, область, індекс) та варіантами без вулиці після тригерів «проживає / зареєстрований / за адресою». Адреси установ (суд, банк, прокуратура) відсіюються за контекстом.
- **НОМЕР:** телефони, IBAN, номери карток, паспорти (серія + 6 цифр) та ID-картки, ІПН/РНОКПП, VIN, номерні знаки, номери військових частин (в/ч), виконавчих проваджень і машино-місць; формати за стандартами плюс ключові слова поруч (ІПН, паспорт, телефон, ДНЗ…).
- **ІНФОРМАЦІЯ:** дати народження і смерті (за контекстом, не всі дати підряд, у т. ч. ISO), email, нікнейми, соцмережі, військові формування (ТЦК та СП, навчальні центри…), державні органи у ролі сторони справи.

### CRF
`crf2.model` (python-crfsuite) навчено в `crf_training/` на реченнях з корпусу судових рішень із синтетично згенерованими даними (формати дат, адреси, нікнейми, номери). Тестова вибірка не використовувалась. Назви ТОВ/ПрАТ навмисно позначено як «не маскувати», бо розмітка їх маскує непослідовно.

## Що і як покращувало результат

| Крок | Що зроблено | Ефект |
|---|---|---|
| Базовий regex | перші правила | середнє .675 |
| Дати лише за контекстом | дати маскуються, якщо поруч «народження/помер» тощо, а не всі підряд | ІНФОРМАЦІЯ P: .13 → .34 |
| Прибрано правила для ТОВ/ПрАТ/ПП | розмітка маскує їх у 7–36% випадків: 182 хибні проти 12 вірних | ІНФОРМАЦІЯ P .34 → .94 |
| Виправлення «площа» в АДРЕСА | «площею 269,6 кв. м» більше не вважається вулицею «площа» | АДРЕСА P: .62 → .95 |
| Звужено суфікси по батькові | «овн» в слові «Верховний» давав понад тисячу хибних ОСОБА | ОСОБА (regex) .826 → .983 |
| Regex-особи до моделі | модель пропускала ПІБ у «за позовом … до» | ризик деанонімізації .080 → .053, ОСОБА R .987 → .998 |
| Держоргани-сторони | орган маскується після «позовом … до», «скарга …», «(далі - …)»; повтори в документі теж | ІНФОРМАЦІЯ F1 .724 → .750 |
| CRF | додаткові кандидати | +.011 до середнього: АДРЕСА R .888 → .927, НОМЕР R .868 → .940 |

## Обмеження

- Правила АДРЕСА, ОСОБА й ІНФОРМАЦІЯ підбирались, зокрема, за аналізом помилок на тесті, тому оцінки трохи оптимістичні. Окремої розміченої валідації немає: train-вибірка містить лише сирі тексти.
- Найслабший тип — ІНФОРМАЦІЯ (P .69 / R .82). Розмітка маскує організації непослідовно, і правилами за формою цього не відрізнити. Далі ростиме дотренування трансформера на всі чотири класи або класифікатор «маскувати чи ні».
- «Військова частина А1234» у розмітці має тип НОМЕР, а не ІНФОРМАЦІЯ.
