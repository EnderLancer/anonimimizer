# Псевдонімізатор персональних даних в українських текстах

Програма знаходить у тексті судового рішення персональні дані (**ОСОБА, АДРЕСА, НОМЕР, ІНФОРМАЦІЯ**) і замінює їх
кодами (`ОСОБА_1`, `НОМЕР_2` …): одна й та сама особа чи значення в межах документа завжди отримує один і той самий код.
Постановка задачі: `Псевдонімізація персональних даних у текстах. Опис завдання.docx`.

Працює **локально**, на CPU, без платних API. Два режими: повний (нейромережа + правила + CRF) і швидкий **regex-режим**
(без нейромережі та без CRF).

## Результати (240 тестових рішень, `data/evaluate.py`)

| | **full** (нейромережа + regex + CRF) | **regex** (лише правила + словник імен) |
|---|---|---|
| **Підсумковий бал** (NER macro F1, IoU ≥ 0.5) | **0.7856** | **0.7182** |
| Strict F1 (межі до символу) | 0.7055 | 0.5890 |
| Deanonymization risk (менше — краще) | 0.080 (69 з 862 осіб) | 0.164 (141 з 862 осіб) |
| Consistency (B³ F1) | 0.995 | 0.993 |
| Час на 240 рішень | ~14 хв (≈3,4 с на рішення, CPU) | ~3 с |
| Пам'ять (пік RSS) | ~7,0 ГБ (вимір на фінальному прогоні; раніше 5,8 ГБ) | ~30 MB |

### Розподіл по класах (м'яке зарахування, IoU ≥ 0.5)

**full:**

| Клас | Precision | Recall | **F1** | TP | FP | FN | Strict F1 |
|---|---|---|---|---|---|---|---|
| ОСОБА | 0.977 | 0.987 | **0.982** | 2789 | 65 | 38 | 0.946 |
| АДРЕСА | 0.738 | 0.665 | **0.700** | 155 | 55 | 78 | 0.470 |
| НОМЕР | 0.932 | 0.888 | **0.910** | 397 | 29 | 50 | 0.879 |
| ІНФОРМАЦІЯ | 0.946 | 0.389 | **0.551** | 70 | 4 | 110 | 0.535 |
| **macro** | 0.898 | 0.732 | **0.786** | | | | 0.706 |

**regex:**

| Клас | Precision | Recall | **F1** | TP | FP | FN |
|---|---|---|---|---|---|---|
| ОСОБА | 0.907 | 0.970 | **0.937** | 2741 | 282 | 86 |
| АДРЕСА | 0.715 | 0.506 | **0.593** | 118 | 47 | 115 |
| НОМЕР | 0.953 | 0.857 | **0.902** | 383 | 19 | 64 |

| **macro** | 0.876 | 0.655 | **0.718** | | | |

Підсумковий бал — середнє F1 по чотирьох класах **з однаковою вагою**, тому рідкісні АДРЕСА та ІНФОРМАЦІЯ (≈11% сутностей)
дають половину балу. Precision помітно вища за recall: правила й моделі обережні й пропускають частину сутностей.

## Як це працює (режим full)

```
текст ──► нейромережа (spaCy uk_ner_web_trf_13class)  ──► ОСОБА  (спани PERS)
      ├─► regex-правила (rules.py)                      ──► НОМЕР / ІНФОРМАЦІЯ / АДРЕСА
      └─► CRF (models/crf2.model)                       ──► НОМЕР / ІНФОРМАЦІЯ / АДРЕСА
                       │
                       ▼
            злиття: ОСОБА від нейромережі фіксується першою; решта кандидатів додається від довшого
            до коротшого, якщо не перетинається з прийнятими  ──►  групування осіб  ──►  коди
```

1. **Нейромережа для імен.** Готова spaCy-модель [`dchaplinsky/uk_ner_web_trf_13class`](https://huggingface.co/dchaplinsky/uk_ner_web_trf_13class)
   (xlm-roberta-large, донавчена на NER-UK 2.0, ліцензія MIT). З її 13 класів беремо лише **PERS** → ОСОБА. Сама по собі вона дає
   F1 0.98 на іменах, але типів «номер», «адреса», «дата народження» не має, тому одна вона набирає лише 0.2455
   (0.98 / 4: решта трьох класів = 0).
2. **Regex-правила** (`solution/pseudonymizer/rules.py`) написані за описом завдання, стандартами форматів і ключовими словами зі
   статистики корпусу рішень 2024:
   - **НОМЕР:** телефони (+380…, з роздільниками), ІПН/РНОКПП у контексті, паспорт і ID-картка, закордонний паспорт, номерні знаки,
     IBAN (крім рахунків установ: казначейство, судовий збір тощо), картки, VIN, IMEI, номер військової частини.
   - **ІНФОРМАЦІЯ:** email, URL, @-нікнейми, соцмережі, дата **одразу після імені** (у ЄДРСР це дата народження), рік
     народження, дати поруч зі словами про смерть.
   - **АДРЕСА:** структурний шаблон «[індекс] [область] [район] [місто] вулиця номер [корпус] [кв.]»; адреси установ (суд,
     прокуратура, банк, АЗС) відсікаються за контекстом.
3. **CRF** (`python-crfsuite`, `solution/models/crf2.model`, 7 МБ) для НОМЕР/ІНФОРМАЦІЯ/АДРЕСА. Навчена на ~53 тис. реченнях із
   корпусу `2024-court-decisions`, де коди замінено вигаданими значеннями (12 форматів дат, адреси в стилі Укрпошти, нікнейми
   тощо). Назви ТОВ/ПрАТ у ЄДРСР здебільшого не маскуються, тому в навчанні вони позначені як «не сутність». Ловить те, що правила
   пропускають, за контекстом.
4. **Групування осіб** (`persons.py`): «Романишин М.», «Романишина», «Мар'яна Романишин» → один код. Відкидаємо відмінкові
   закінчення й порівнюємо основи слів.

### Режим regex (без нейромережі й CRF)

ОСОБА знаходиться за структурою запису (ПІБ із по батькові, «Прізвище І.Б.», «І.Б. Прізвище», пара ім'я+прізвище) та за
**словником імен** (5 267 слів), який побудовано з відкритих корпусів NER-UK та Ukr-Synth (`resources/names_vocab.txt`), і списком
часто вживаних «не імен» (`resources/common_caps.txt`). Решта типів — ті самі `rules.py`. Режим швидкий (≈13 мс на рішення) і не
потребує завантажень, але слабший на іменах (F1 0.937 проти 0.982) і особливо на АДРЕСА (0.593 проти 0.700).

Застереження: словник імен частково походить із Ukr-Synth (синтетичний корпус), тож на справжніх неформальних текстах з рідкісними
іменами режим regex узагальнюватиметься гірше за нейромережу.

## Запуск

```bash
pip install -r solution/requirements.txt       # лише для режиму full

# повний режим (нейромережа шукається локально; якщо немає — завантажується один раз, ~1,3 ГБ)
python solution/predict.py inputs.jsonl submission.jsonl

# швидкий режим без нейромережі
python solution/predict.py inputs.jsonl submission.jsonl --mode regex
```

Формат: вхід — JSONL з полями `id`, `original`; вихід — JSONL `{"id", "annotations": [{"start","end","pseudonym"}]}`
(позиції символів, `end` не включно). Підготувати вхід із тестового набору і оцінити:

```bash
python scripts/split_test_data.py data/test/court_cases.jsonl out/inputs.jsonl
python solution/predict.py out/inputs.jsonl out/submission.jsonl
python data/evaluate.py data/test/court_cases.jsonl out/submission.jsonl
```

### Де береться модель

`solution/pseudonymizer/ner.py` шукає теку моделі в такому порядку: змінна `ANON_SPACY_MODEL` → `solution/models/spacy/` →
`solution/models/` → `models/` у корені та поруч із репозиторієм. Якщо моделі немає, вона завантажується з Hugging Face у
`solution/models/spacy/` (потрібен інтернет лише для цього кроку). Лише завантажити: `python solution/download_models.py`.
CRF-модель лежить у репозиторії, завантажувати її не треба. Додаткові опції: `--model-dir`, `--chunk-chars N` (ділити довгі
тексти на шматки для нейромережі), `--stats` (час і пік пам'яті).

## Відтворення навчання CRF і словників

```bash
python solution/training/download_train_data.py            # NER-UK, Ukr-Synth (корпус рішень уже в data/train, git LFS)
python solution/training/build_train2.py                   # train2.pkl (~53 тис. речень)
python solution/training/train_crf.py                      # -> solution/models/crf2.model  (~15 хв, CPU)
python solution/training/build_name_vocab.py               # словники для режиму regex
```

## Структура

```
solution/
  predict.py                 точка входу (CLI)
  download_models.py         завантаження нейромережі
  requirements.txt
  models/crf2.model          CRF-модель (spacy-модель завантажується окремо в models/spacy/)
  pseudonymizer/
    pipeline.py              злиття кандидатів, групування, коди
    ner.py                   пошук/завантаження/виклик spaCy-моделі
    rules.py                 regex-правила (НОМЕР, ІНФОРМАЦІЯ, АДРЕСА)
    crf.py, text.py          CRF-інференс, токенізація й ознаки
    persons.py               групування згадок однієї особи
    regex_only.py            режим без нейромережі
    resources/               names_vocab.txt, common_caps.txt
  training/                  скрипти навчання та побудови словників
  baselines/team_regex_baseline.py   початковий базовий regex команди (для порівняння)
results/results.json         метрики фінальних запусків
```

## Чесні застереження

- Тестова вибірка (поля `annotations`/`pseudonymized`) **не використовувалась для навчання чи підбору параметрів**. Правила писалися
  за описом завдання та статистикою тренувального корпусу. Проте результат тесту бачили після кожної версії, тому вибір наступних
  кроків трохи залежить від тесту, а підсумок 0.786 слід вважати оптимістичною оцінкою для нових текстів.
- Пам'ять full-режиму близько 7 ГБ — майже на межі ліміту 8 ГБ (різні прогони давали 5,8–7,3 ГБ); для запасу є `--chunk-chars`, ефект на бал не перевірявся.
- Не перевірялось: запуск у середовищі з жорстким обмеженням 8 GB, збірка Docker-образу, робота на неформальних текстах.
- Recall ІНФОРМАЦІЇ (39%) та АДРЕСА (67%) лишаються найслабшими місцями. Це наступний напрямок.
