# План: оцінка NER-моделі поза судовим доменом (OOD)

Дата: 2026-10-09. Статус: план, не реалізовано.

## Мета

Показати, як модель, донавчена на реєстрових рішеннях (`davidmelash/wechsel_base` і наступні), знаходить
ОСОБА / АДРЕСА / НОМЕР / ІНФОРМАЦІЯ у текстах інших жанрів: новини, Вікіпедія, загальний веб (оголошення,
збори, сторінки компаній, художня література). Результат: невеликий gold-набір (~180 документів) у схемі
тесту, скрипт оцінки з розбивкою за джерелом і таблиця в README.

## Що вже є і використовується без змін

- `data/evaluate.py` — метрики організаторів; gold-формат `{id, original, annotations: [{start, end, pseudonym}]}`.
  Інших полів не вимагає, тож OOD-файл може нести ще `source`, `url`, `license`. Не змінюємо.
- `run.py --mode … --ner hf:…` і `train/scripts/predict.py` пишуть submission для будь-якого JSONL з `id` + `original`.
- `data/link_persons.py` — зразок потоку «export задач → агенти Claude Code пишуть `answers/<id>.json` → import».
  API-ключа локально немає, розмітку робимо так само агентами.
- CI `ner-models.yml` приймає override `data=…`, тож OOD-файл проганяється через нього без правок.

| Джерело | Ліцензія | Поля | Що беремо | Як читаємо |
|---|---|---|---|---|
| `zeusfsx/ukrainian-news` | unknown (копірайт сайтів-власників) | `id, url, title, text (з HTML), owner, datetime` | новини 2022+ (війна: бригади, військові частини, ТЦК, коди А1234; збори: IBAN, картки, телефони), регіональні новини (адреси подій, ДТП, оголошення) | `load_dataset(streaming=True)`: перші ~50 тис. рядків `vol1` (файл 7,9 ГБ, читаємо послідовно скільки треба); HTML знімаємо `html.parser` |
| `HuggingFaceFW/finewiki`, config `uk` | CC-BY-SA 4.0 / GFDL | `text` (чистий, markdown-подібний), `title`, `url`, `infoboxes` | біографії (дати народження/смерті = ІНФОРМАЦІЯ, латинські імена), статті про військові формування (назви частин, А-номери), випадкові статті без персональних даних (контроль хибних спрацювань) | streaming по parquet (4 шарди по 1,4 ГБ, читаються по row group) |
| `Goader/kobza` | CC0 (заявлено авторами збірки) | `text, id, url, timestamp, subsource, source` (`fineweb-2`, `hplt-2.0`, `cultura-x`, `ubertext2.0`, `ukrainian-news`) | веб (`hplt-2.0` / `fineweb-2`: контакти, оголошення, prom.ua, благодійні збори — телефони, адреси, IBAN, email), `ubertext2.0` (художня література, блоги) | streaming одного-двох шардів (1,7 ГБ кожен), фільтр за `source` локально |
| `lang-uk/malyuk` | у картці ліцензії немає | `id, compound_id, text` | — | не використовуємо: це UberText 2.0 + OSCAR + ukrainian-news + wiki, усе це є в kobza і finewiki з чіткішими ліцензіями; запасний варіант для `ubertext` |

Готовий gold лише для ОСОБА: `Goader/ner-uk-2.0` (NER-UK 2.0, CC-BY-NC-SA 4.0; типи PERS, LOC, ORG, DOC, DATE…;
новини NashiGroshi + корпус БрУК; test split 169 текстів). PERS → ОСОБА дає незалежну перевірку ОСОБА без нашої
розмітки; АДРЕСА / НОМЕР / ІНФОРМАЦІЯ не покриває (LOC — це міста, не адреси; DATE — усі дати). Бонусний крок 7.

Перевірено 2026-10-09: `/search` і `/filter` datasets-server для цих наборів нестабільні («the dataset index is
loading», «Unexpected error»), тому вибірка робиться streaming-читанням і локальними regex; `/rows` — лише
як запасний спосіб глянути на дані.

Ліцензійна увага: finewiki (CC-BY-SA, вказуємо URL статті) і kobza (CC0) можна публікувати; тексти
`zeusfsx/ukrainian-news` тримаємо в репозиторії як короткі уривки для дослідження, на Hugging Face не
викладаємо (або беремо новини з kobza, `source = ukrainian-news`, де ту саму збірку перевидано під CC0).

## Склад набору

Ціль ~180 документів, кожен 400–3 000 символів, обрізання на межі абзацу. Щоб F1 за типом не був шумом,
потрібно щонайменше 50 gold-згадок кожного типу; квоти добираємо regex-ами за ключовими словами, а не моделлю
(відбір моделлю завищив би recall).

| Джерело | Підвибірка | К-сть | Ключові слова відбору | Очікувані типи |
|---|---|---|---|---|
| news | воєнні новини | 25 | `бригад`, `військов(а|ої) частин`, `ТЦК`, `\bА\d{4}\b`, `батальйон`, `полк` | ІНФОРМАЦІЯ (назви частин), НОМЕР (коди), ОСОБА |
| news | збори, оголошення | 15 | `IBAN`, `UA\d{27}`, `\+380`, `картк`, `@`, `моно` | НОМЕР, ІНФОРМАЦІЯ (email), АДРЕСА |
| news | випадкові регіональні | 20 | — (owner ≠ центральні агентства) | ОСОБА, АДРЕСА подій |
| wiki | біографії | 25 | infobox «Народився» / «Дата народження», дужки `(\d{1,2} \w+ \d{4}` у першому абзаці | ОСОБА (у т. ч. латиниця), ІНФОРМАЦІЯ (дати народження/смерті) |
| wiki | військові формування | 15 | `окрема … бригада`, `військова частина`, `\bА\d{4}\b`, infobox «Військове формування» | ІНФОРМАЦІЯ, НОМЕР, ОСОБА (командири) |
| wiki | випадкові | 20 | — | мало або нічого (контроль хибних спрацювань) |
| web (kobza) | контакти, оголошення | 20 | `source ∈ {hplt-2.0, fineweb-2}`; `за адресою`, `вул\.`, `тел`, `\+380`, `e-?mail`, `@` | АДРЕСА, НОМЕР, ІНФОРМАЦІЯ (email) |
| web (kobza) | художня література, блоги | 20 | `source = ubertext2.0`, `subsource ≠ news` | ОСОБА (вигадані персонажі теж) |
| web (kobza) | випадкові | 20 | — | що трапиться |

Фільтри кандидатів: частка кирилиці ≥ 0,8 і відсутність російських маркерів (`ы`, `э`, `ъ`, `ё`); дедуплікація
(точна і 5-грамна, поріг 0,5, як у `datagen/src/silver/exclude.py`); викидаємо тексти, схожі на судові рішення
(`ВСТАНОВИВ`, `справа №`, `Іменем України`), щоб набір лишався поза доменом; HTML → абзаци (`<p>` → порожній рядок,
`<img>`, `<script>` геть, текст посилань лишаємо).

## Інструкція розмітки (`data/ood/GUIDELINES.md`)

За основу — визначення організаторів і реєстрова конвенція (пам'ять: ІНФОРМАЦІЯ = дати народження/смерті,
email, назви військових частин; код частини А1234 = НОМЕР). Адаптація до інших жанрів:

- ОСОБА — кожне ім'я фізичної особи: публічні особи теж (модель не має знати, хто публічний), іноземні імена
  латиницею, ініціали, прізвище окремо, персонажі художніх текстів. Не ОСОБА: назви вулиць, компаній, кораблів
  на честь людей (вул. Шевченка — частина АДРЕСА); присвійні прикметники («Шевченкові твори»).
- АДРЕСА — поштова адреса (вулиця + будинок, населений пункт + вулиця), локація після «за адресою». Не АДРЕСА:
  саме місто, область, країна, район без вулиці.
- НОМЕР — телефон, IBAN, номер картки, РНОКПП, паспорт, номерний знак, VIN, код військової частини (лише
  `А1234`, слова «військова частина» лишаються текстом, як у тесті), номери справ / проваджень, рахунків.
  Не НОМЕР: дати, ціни, відсотки, номери статей законів, поштові індекси окремо (у складі адреси — АДРЕСА).
- ІНФОРМАЦІЯ — дата народження або смерті, прив'язана до людини («народився 25 березня 1975 року», дужки у
  вікі-біографіях «(25 березня 1975, Гельсінкі — …)»: дати так, місце — ні); email; назва військової частини
  або формування («93-тя окрема механізована бригада», «Печерський районний ТЦК та СП»). Не ІНФОРМАЦІЯ:
  Міністерство оборони, Генштаб, ЗСУ як ціле, інші дати, URL.
- Межі — як у реєстрі: повне ім'я без розділових знаків довкола, дата разом з «року», код частини без «№».
- Зв'язування: одна людина — один псевдонім `ОСОБА_n` у документі (метрики consistency і by-name risk);
  для інших типів один псевдонім на один унікальний рядок.
- Кожна сутність несе ще `kind` (`phone`, `iban`, `card`, `plate`, `unit_code`, `dob`, `death`, `email`,
  `unit_name`, `residence`, `property`, …) — для recall за підвидом, у gold-файл іде окремим полем.

Відкриті рішення (значення за замовчуванням, якщо не сказано інакше): публічні особи = ОСОБА (так);
частково приховані телефони «+380 67 ***» = НОМЕР (так); повторення імені в заголовку — звичайна згадка;
військові відомства (МОУ, Генштаб) — не ІНФОРМАЦІЯ.

## Потік розмітки (агентами Claude Code, без API)

1. `python data/build_ood.py sample --out data/ood/01_candidates.jsonl` — вибірка за квотами, `id` вигляду
   `news:a1b2c3d4e5f6` (джерело + хеш тексту), поля `original, source, subsource, url, title, license`.
2. `python data/build_ood.py export data/ood/tasks/` — `INSTRUCTIONS.md` (інструкція розмітки) + `<id>.md`
   на документ. Агент пише `data/ood/answers/<id>.json`:
   `{"entities": [{"text": "Віктор Ющенко", "type": "ОСОБА", "kind": null, "person": "p1"}, …]}`.
   Агент дає рядки сутностей, не зміщення: importer сам знаходить усі входження цілим словом і повідомляє, що
   не знайшлося або перетнулося (довший рядок виграє). Різні відмінки («Ющенко», «Ющенка») агент перелічує
   окремо з одним `person`. Перший прохід — без підказок моделі, щоб розмітка не успадкувала її помилки.
3. Другий прохід (арбітраж): `build_ood.py diff` зводить розбіжності між gold першого проходу і виходом
   пайплайна (`run.py --mode full --ner hf:davidmelash/wechsel_base`) у `tasks_adj/<id>.md`; інший агент
   вирішує кожну розбіжність за інструкцією; `import --adjudicate` застосовує рішення. 30 документів розмічаються
   двічі незалежно — F1 між двома розмітками йде в README як стеля для моделі.
4. `python data/build_ood.py import data/ood/answers/ --out data/ood/ood_cases.jsonl` — перевірка (межі в
   тексті, без перетинів, тип з `TYPES`, узгодженість `person`), псевдоніми за порядком першої появи,
   `pseudonymized` як у тесті, `data/ood/REPORT.md` з кількостями за джерелом і типом.
5. Ручна перевірка: `build_ood.py check --sample 20` друкує документи з позначками `[Ющенко|ОСОБА_1]` для
   читання користувачем; при нестачі типу (< 50 згадок) — добір документів і повернення на крок 2.
6. Приблизно 15 агентів по 12 документів (як для `person_links.json`), 1–2 години на прохід.

## Скрипт оцінки

`python data/evaluate_ood.py data/ood/ood_cases.jsonl results/ood_full.jsonl [results/ood_model.jsonl …] [--by source|subsource] [--json] [--bootstrap 1000]`:

- імпортує `evaluate.evaluate` і рахує на всьому наборі та на кожному підмножині за `source` (gold-рядки
  фільтруються за полем, submission — за `id`);
- таблиця: рядки — джерела + «усього»; стовпці — F1 (P / R) за типом, macro F1, strict F1, by-name risk, B³;
- додаткові OOD-показники: хибні спрацювання на 1 000 символів у документах без gold-сутностей типу
  (надмірне спрацювання на чистому тексті); recall за `kind` (через `evaluate.match` на gold-підмножинах);
- кілька submission поруч — порівняння режимів (`model` / `model_regex` / `full`) і моделей (spaCy-базова,
  `wechsel_base`, наступні);
- бутстреп по документах для 95 % інтервалу (набір малий, за джерелом буде ±0,05–0,10 — порівнюємо лише
  великі різниці);
- `--json` для CI.

Передбачення: `python run.py data/ood/ood_cases.jsonl results/ood_full.jsonl --mode full --ner hf:davidmelash/wechsel_base`
(режими `model`, `model_regex`, `regex` — так само), окремо `uv run train/scripts/predict.py` для чистої моделі
без постобробки `run.py`.

- `evaluate.yml`: job `ood` — `regex`, `model_regex`, `full` на `data/ood/ood_cases.jsonl` з NER за замовчуванням
  (~180 документів, дешево) → `evaluate_ood.py --json` → таблиця в summary.
- `ner-models.yml`: уже вміє `data=data/ood/ood_cases.jsonl`; дописати це в коментар-шапку як приклад.
- README: розділ «Поза доменом» — таблиця за джерелом для базового пайплайна і `wechsel_base`, три головні
  класи помилок (гіпотези для перевірки: усі дати як ІНФОРМАЦІЯ; організації не-військові як ІНФОРМАЦІЯ;
  латинські імена; адреси без «за адресою»; телефони, бо в silver вони всі замасковані).

## Порядок робіт і оцінка часу

1. Інструкція розмітки, відповіді на відкриті рішення — 0,5 дня.
2. `build_ood.py sample` з фільтрами, перший пул кандидатів, перевірка квот regex-ами — 0,5 дня.
3. Перший прохід розмітки агентами, import, звіт, добір типів з нестачею — 0,5 дня (1–2 години машинного часу).
4. Арбітраж і підмножина подвійної розмітки — 0,5 дня.
5. `evaluate_ood.py` і тести — 0,5 дня.
6. Прогін усіх режимів і моделей, таблиця в README, job у CI — 0,5 дня.
7. Бонус: PERS → ОСОБА на NER-UK 2.0 test (169 текстів) тим самим `evaluate_ood.py` — 0,25 дня.

## Ризики

- Ліцензія новин `zeusfsx` — тримаємо в репозиторії як дослідницькі уривки, не публікуємо на HF; альтернатива —
  новини з kobza. Рішення за користувачем.
- Реєстрова конвенція проти OOD: модель вивчила «код частини → НОМЕР», «військовий орган як сторона →
  ІНФОРМАЦІЯ». Інструкція тримає одну лінію; відомі конфлікти конвенцій перелічуємо в README замість другого
  варіанта скорингу.
- Розмітка агентами успадковує їхні помилки: перший прохід без моделі, арбітраж другим агентом, 30 документів
  подвійно, ручна вибірка користувачем.
- Малий набір: довірчі інтервали широкі; скрипт друкує їх, README порівнює лише різниці поза інтервалом.
